# The Gemini subscription, app side

This package owns both halves of the Gemini sign-in. `packages/coding-agent/src/gemini-auth.ts` holds the wire: the installed-app client the reference CLI ships, the token endpoint, the refresh policy, the credential store, and the bearer provider. `packages/coding-agent/src/gemini-login.ts` holds the two sign-in shapes — loopback and paste — the CLI wrappers, and the hooks the REPL drives. The model wire that spends the bearer, the `gemini-code-assist` adapter, lives in `packages/ai`; its long-form notes are in ai-layer.md.

## The credential store

The store is `createGeminiCredentialStore` (`packages/coding-agent/src/gemini-auth.ts:313`). It is the Claude store's shape — keychain first through `Bun.secrets`, a 0600 file when no secret service answers — under its own keychain entry: service `labunbun`, name `gemini` (`packages/coding-agent/src/gemini-auth.ts:23`), so a sign-out of one subscription cannot touch another.

- The fallback is a 0600 file at `~/.labunbun/gemini-oauth.json` (`packages/coding-agent/src/gemini-auth.ts:315`), written through a temp file and a rename so a reader never sees half a token (`packages/coding-agent/src/gemini-auth.ts:358`). The fallback says so once, out loud: the no-keychain wording (`packages/coding-agent/src/gemini-auth.ts:394`) and the keychain-refused variant (`packages/coding-agent/src/gemini-auth.ts:390`).
- Load reads the keychain first and falls through to the file when the keychain has no entry or cannot answer (`packages/coding-agent/src/gemini-auth.ts:362`). One entry that IS present is one answer: a malformed keychain entry resolves to null and does not fall through to a file from another era. Save writes the keychain and removes any fallback-era file in the same breath (`packages/coding-agent/src/gemini-auth.ts:380`), so the two can never disagree about which token is current. Clear empties both (`packages/coding-agent/src/gemini-auth.ts:398`), because a sign-out that leaves one copy behind is not a sign-out.
- The stored shape (`packages/coding-agent/src/gemini-auth.ts:156`) allows an empty `refreshToken` on purpose: a re-consent Google has already recorded comes back without one, and refusing that answer would lock the user out of the sign-in that just succeeded. The provider reports the missing refresh honestly at mint time instead.
- Tests always inject the keychain (`keychain: null` or a fake). The default probe has no test on purpose — see the gaps below.

## The sign-in flow

Both shapes use the installed-app client the reference CLI registers: a client id and the non-confidential secret that ships with it (`packages/coding-agent/src/gemini-auth.ts:38`) — the pair spelled in adjacent pieces so no single literal matches a credential scanner. The consent asks for the `cloud-platform` and `userinfo` scopes (`packages/coding-agent/src/gemini-auth.ts:47`).

- The loopback flow runs first: a random port, the `/oauth2callback` path (`packages/coding-agent/src/gemini-login.ts:38`), and state alone — this redirect URI carries no PKCE challenge, so the URL is built from the port the listener actually holds (`packages/coding-agent/src/gemini-login.ts:347`) and the state is the one the listener waits for. The listener waits `GEMINI_LOGIN_TIMEOUT_MS`, five minutes (`packages/coding-agent/src/gemini-login.ts:44`).
- The paste flow is the repair for a machine whose loopback no browser can reach: redirect `https://codeassist.google.com/authcode` (`packages/coding-agent/src/gemini-login.ts:41`), PKCE S256 (`packages/coding-agent/src/gemini-login.ts:61`), and a five-minute budget for the code (`packages/coding-agent/src/gemini-login.ts:47`). The paste accepts the page's own URL as well as the bare code, because the `code` parameter is read out of it (`packages/coding-agent/src/gemini-login.ts:130`). A paste cannot carry the state back and none is demanded: the PKCE verifier is what binds the redemption to this attempt.
- `beginGeminiHeadlessLogin` draws fresh PKCE and state and builds the paste URL (`packages/coding-agent/src/gemini-login.ts:106`); `PendingGeminiLogin` (`packages/coding-agent/src/gemini-login.ts:98`) is what the caller keeps between the two halves, and `completeGeminiLogin` is the second half (`packages/coding-agent/src/gemini-login.ts:191`).
- `geminiLoginFlow` is the whole sign-in (`packages/coding-agent/src/gemini-login.ts:323`). The loopback flow runs first; a listener that cannot come up at all hands off to the paste flow, and `headless: true` asks for the paste flow up front. When a caller gives no `askCode`, the paste flow returns `{ kind: "pending" }` (`packages/coding-agent/src/gemini-login.ts:256`) so a caller with somewhere to keep it — the REPL — can ask later; the CLI passes a terminal asker instead.
- The browser flow sends no `prompt=consent` parameter — the reference implementation sends none — so a re-consent can come back without a refresh token; that is the empty-refresh case the credential shape above answers.
- The refresh policy is eager: five minutes before expiry (`packages/coding-agent/src/gemini-auth.ts:56`), with a fallback window of 3.3 hours for a credential the issuer gave no lifetime (`packages/coding-agent/src/gemini-auth.ts:64`; the rule at `packages/coding-agent/src/gemini-auth.ts:451`). The provider the transports spend is built by `createGeminiTokenProvider` (`packages/coding-agent/src/gemini-auth.ts:471`); `createGeminiCredentials` is the app-facing factory (`packages/coding-agent/src/gemini-auth.ts:544`).
- `geminiSignedInLine` is the one sentence both callers show after a successful sign-in (`packages/coding-agent/src/gemini-login.ts:363`).
- `clearGeminiSubscription` removes the stored credential, revokes the refresh token — or the access token when no refresh exists — at the issuer best effort (`packages/coding-agent/src/gemini-login.ts:380`), and reports whether one was there: a machine that cannot reach Google still signs out, and one that can leaves nothing behind to revoke later.
- The CLI wrappers are `runGeminiLoginCli` (`packages/coding-agent/src/gemini-login.ts:445`) and `runGeminiLogoutCli` (`packages/coding-agent/src/gemini-login.ts:477`). The login wrapper reads a paste from the terminal when the browser path is unavailable.

## What the app wires

- Both transports pass the token provider to `createTrackedStreamFn` beside the Claude and ChatGPT ones: the REPL (`packages/coding-agent/src/interactive.ts:774`, `packages/coding-agent/src/interactive.ts:775-780`), a `-p` run (`packages/coding-agent/src/headless.ts:481`, `packages/coding-agent/src/headless.ts:484`), and the ACP server (`packages/coding-agent/src/acp.ts:1071`). How the adapter decides which bearer signs a request — and that these model rows have no API-key fallback — lives in ai-layer.md.
- The REPL commands are `/login gemini` and `/logout gemini` (`packages/coding-agent/src/interactive.ts:4723`, `packages/coding-agent/src/interactive.ts:4853`). The paste half parks a pending login in module state (`packages/coding-agent/src/interactive.ts:3280`) until `/login gemini <code>` hands the code back; a sign-in in flight holds a flag (`packages/coding-agent/src/interactive.ts:3281`) so a second one is refused.
- The hooks behind both commands are injectable through the context (`packages/coding-agent/src/interactive.ts:3095`; the default wiring at `packages/coding-agent/src/interactive.ts:3302`), so a test — and an embedder — can drive both commands without a browser, a network, or the real keychain of the machine running them.
- The availability displays read the Gemini flag like the other subscriptions: `unrunnableSuffix` (`packages/coding-agent/src/credential-presence.ts:105`), `missingCredentialNotice` (`packages/coding-agent/src/credential-presence.ts:121`) and the store probe `detectSubscriptionSignIns` (`packages/coding-agent/src/credential-presence.ts:49`).
- The CLI subcommands are `labunbun login gemini` and `labunbun logout gemini`. The provider word is consumed while parsing (`packages/coding-agent/src/main.ts:144`) and the dispatch picks the Gemini wrappers (`packages/coding-agent/src/main.ts:358`, `packages/coding-agent/src/main.ts:363`); the help lists the word (`packages/coding-agent/src/main.ts:248`).

## Known gaps

- A signed-in Gemini subscription is not a key in any sense: the wire's rows name no key variable, and a request without a grant gets the adapter's own refusal telling the user to `run /login` (`packages/ai/src/providers/gemini-code-assist.ts:540`), shown at once because the refusal carries the invalid-grant mark the retry wrapper fast-paths (`packages/ai/src/retry.ts:226`).
- Three paths have no test that can run without touching an operator's own machine: the system-keychain probe, the transport wiring lines, and the `main()` subcommand dispatch. The parse of the provider word is tested at the parse layer (`smoke.test.ts`).
- The loopback flow against the real Google consent screen is a real-machine acceptance item: the registered redirect, the consent page, and whether the returned grant carries a refresh token cannot be verified from tests. The paste exchange is tested against a fake fetch, so the real endpoint's error shapes are unverified until a machine runs them.
- The 0600 file-mode assertion is POSIX-only; on Windows the mode check is skipped by design. CI runs the POSIX check on every push.
