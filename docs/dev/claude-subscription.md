# The Claude subscription, app side

`packages/ai` owns the wire: PKCE, the authorize URL, the token endpoint, and the bearer-token provider (`providers/anthropic-oauth.ts`; its long-form notes are in ai-layer.md). This document covers the app around it: where the credential lives between runs, the two shapes of the sign-in, and the commands that drive them.

## The credential store

The store is `createClaudeCredentialStore` (`packages/coding-agent/src/claude-auth.ts:56`). The OS keychain is the first choice, reached through `Bun.secrets`: the Windows Credential Manager, the macOS keychain, and libsecret on Linux. The probe for it is structural (`packages/coding-agent/src/claude-auth.ts:41`), so the module loads on a runtime without that API and answers "no keychain" instead of throwing.

- The fallback is a 0600 file at `~/.labunbun/.credentials.json`, written through a temp file and a rename so a reader never sees half a token (`packages/coding-agent/src/claude-auth.ts:87`). A machine without a secret service is a real machine — a container, a CI runner — and the fallback says so once, out loud (`packages/coding-agent/src/claude-auth.ts:63`). The warning is the contract: a fallback nobody is told about is a fallback the user believes is a keychain.
- Load reads the keychain first and falls through to the file when the keychain has no entry or cannot answer (`packages/coding-agent/src/claude-auth.ts:105`). One entry that IS present is one answer: a malformed keychain entry resolves to null and does not fall through to a file from another era (`packages/coding-agent/src/claude-auth.ts:111`). Two stores, one credential — the second is never consulted to paper over the first.
- Save writes the keychain and removes any fallback-era file in the same breath (`packages/coding-agent/src/claude-auth.ts:123`), so the two can never disagree about which token is current. Clear empties both (`packages/coding-agent/src/claude-auth.ts:141`), because a sign-out that leaves one copy behind is not a sign-out.
- Tests always inject the keychain (`keychain: null` or a fake). The default probe has no test on purpose — see the gaps below.

## The sign-in flow

The flow is `claude-login.ts`. It has two shapes, and both end in the same exchange and the same store.

- `beginClaudeLogin` draws fresh PKCE and state and builds the authorize URL (`packages/coding-agent/src/claude-login.ts:47`). The default redirect is the console's registered localhost callback on port 1455; the manual shape overrides it with the console's paste page.
- `completeClaudeLogin` turns what came back into a stored credential (`packages/coding-agent/src/claude-login.ts:79`). A paste without a state is accepted — the page shows `code#state`, and a user who copied only the code should not be told the code is wrong. A paste with a DIFFERENT state is refused before any exchange: that is a redirect from some other sign-in, and its code would bind the session to an account the user did not open here.
- `startClaudeCallbackServer` binds the shared loopback listener to the console's path and error type (`packages/coding-agent/src/claude-login.ts:114`; the listener itself is `callback-server.ts`, shared with the ChatGPT flow). A redirect whose state does not match answers 400 and KEEPS listening (`packages/coding-agent/src/callback-server.ts:115`) — an error redirect included, because the console's own error responses carry the state back: a stray request to the port — a scanner, an old tab, any page the user happens to visit — must not end the sign-in the user is still completing. A callback carrying `error` rejects with the console's reason; a matching state with no code rejects; a timeout, an abort, and a bind failure each have their own exit. A settled wait releases the port, and the response asks the browser not to keep the connection, so the listener closes the moment the page is delivered.
- The resolver's promise rejects as well as resolves, and the caller may attach a microtask later; the listener holds a catch handle internally so a fast rejection cannot surface as an unhandled rejection (`packages/coding-agent/src/callback-server.ts:80`).
- `claudeLoginFlow` is the whole sign-in (`packages/coding-agent/src/claude-login.ts:161`). The browser path opens the URL, listens, and completes. When the port cannot be bound — another instance holds it, a policy forbids listening — the flow falls back to the console's manual page, opens it too, and either reads a paste through `askCode` or returns the pending login (`packages/coding-agent/src/claude-login.ts:177`). The returned pending login is what lets the REPL complete a sign-in minutes after the URL was printed.
- `openSystemBrowser` is best effort, always (`packages/coding-agent/src/callback-server.ts:187`, re-exported at `packages/coding-agent/src/claude-login.ts:27`): the URL is printed either way, so a missing opener is a copy and a paste. On Windows the URL goes through a verbatim `cmd /c start` string, because the URL carries `&` and cmd would read it as a command separator.
- The CLI wrappers are `runClaudeLoginCli` and `runClaudeLogoutCli` (`packages/coding-agent/src/claude-login.ts:281`). Their paste reader refuses a non-terminal stdin up front (`packages/coding-agent/src/claude-login.ts:261`) instead of waiting forever on an input nobody can type into.

## What the app wires

- Both transports hand the same token provider to `createTrackedStreamFn`: the REPL (`packages/coding-agent/src/interactive.ts:724`, `packages/coding-agent/src/interactive.ts:727`) and a `-p` run (`packages/coding-agent/src/headless.ts:409`, `packages/coding-agent/src/headless.ts:414`). The anthropic adapter decides what to do with it per request, including the precedence order — a per-call key outranks the stored login, which outranks the environment's key. That matrix lives in ai-layer.md.
- The REPL commands are `/login` and `/logout` (`packages/coding-agent/src/interactive.ts:3960`, `packages/coding-agent/src/interactive.ts:4111`). The sign-in a manual paste belongs to is module state (`packages/coding-agent/src/interactive.ts:2788-2797`): there is one REPL per process, and a session swap must not discard a sign-in in progress. The hooks behind both commands are injectable through the context (`packages/coding-agent/src/interactive.ts:2613`; the default wiring at `packages/coding-agent/src/interactive.ts:2808-2816`), so a test — and an embedder — can drive `/login` and `/logout` without a browser, a network, or the real keychain of the machine running them.
- The CLI subcommands are `labunbun login` and `labunbun logout` (`packages/coding-agent/src/main.ts:356`). They run before the API-key check, like `yoshi`: signing in is how someone gets a working setup, so it cannot require one first. An optional provider word routes them — see chatgpt-subscription.md.

## Known gaps

- A signed-in subscription does not turn the Anthropic catalog probe on. Discovery's gate is the environment and the settings, and the probe bullet in ai-layer.md's Discovery section is the honest record.
- Three paths have no test that can run without touching an operator's own machine: the system-keychain probe, the two transport wiring lines, and the `main()` subcommand dispatch. The mutation driver for the batch left exactly those survivors, and they are listed in the commit message rather than covered by a test that would have to reach a real keychain or open a real browser.
- The 0600 file-mode assertion is POSIX-only; on Windows the mode check is skipped, and the batch's file-mode mutant survives there by design. CI runs the POSIX check on every push.
